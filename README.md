# neb-x

NebulaX Hackathon submission for **Problem Statement 3 — Train Condition Monitoring**.

Problem statement source:
[aochinwen/NebulaX-Hackathon-ProblemStatement](https://github.com/aochinwen/NebulaX-Hackathon-ProblemStatement) (`PS3/`)

## The problem

Detect faults and estimate degradation from raw rail-vehicle sensor time series across four
independent subsystems, each worth 25% of the Overall Score.

| Subsystem | Task | Metric |
|---|---|---|
| Door | Find each door open/close cycle in a continuous stream and classify it `Normal` vs `Abnormal resistance` | IoU-weighted F1 |
| ACV | Rank the cars in a train from most- to least-likely to have a refrigerant leak | Linear rank-decay |
| Rail Corrugation | Classify `Normal` / `Side I` / `Side II` from axle-box vibration | Macro F1 |
| SHM | Estimate cumulative fatigue damage from dynamic stress data | `max(0, 1 − MAPE)` |

Each subsystem's authoritative definition — schema, labels, exact scoring formula with a worked
example — is its info kit under [docs/](docs/).

## Deliverables

1. A demo video (≤3 min) of the app in use end to end.
2. `predictions.zip` — one `*_predictions.csv` per subsystem attempted, flat at the top level.
3. An app that lets a non-technical user upload a data file and get a prediction back. The
   submitted predictions must be generated by running the held-out test files through it.

## Layout

```
neb-x/
├── docs/                         the organisers' spec and per-subsystem info kits (read-only)
├── reference/submission_format/  the four example prediction CSVs — the schema contract
├── data/                         raw datasets, gitignored (~6 GB) — see data/README.md
├── src/
│   ├── common/                   subsystem-agnostic: paths, io, splits, features, metrics, registry
│   ├── door/ acv/ rail/ shm/     one package per subsystem, identical file roles
│   ├── app/                      the non-technical UI
│   └── submission/               schema validation and predictions.zip packaging
├── scripts/                      thin entry-point wrappers
└── outputs/                      models, predictions, plots, logs, packaged submission (gitignored)
```

`src/` and `scripts/` are scaffolding — no code yet. Conventions are in
[CLAUDE.md](CLAUDE.md) and [.claude/memory/project-structure.md](.claude/memory/project-structure.md).
